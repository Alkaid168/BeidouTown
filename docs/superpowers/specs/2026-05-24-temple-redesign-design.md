# 占卜寺庙重做设计

**日期：** 2026-05-24  
**范围：** 重做 `temple` 功能的主页、抽牌流程、AI 解读展示与多牌阵支持。

---

## 目标

把当前只支持单一三张牌历史列表的“寺庙”重做为一个更有仪式感的占卜体验：

- 主页先选择占卜模式
- 进入单独的占卜页面提问
- 牌阵在中央浮现
- 用户必须按顺序翻牌
- 全部翻完后自动开始 AI 解读
- 解读结果在同页底部流式出现
- 页面宽度、外壳结构、标题气质与小酒馆 / 树洞邮局保持一致

这次只使用 **22 张大阿卡那**，并保留 **正位 / 逆位**。

---

## 最终交互结构

采用 **两页式结构**。

### 1. 寺庙主页 `/temple`

职责：只负责展示模式入口，不展示历史记录。

页面内容：
- 使用背景图 `F:\CODES\北斗镇\占卜寺庙背景图.png`
- 左上角标题：`占卜寺庙`
- 英文 eyebrow：可用 `TEMPLE` 或 `ORACLE TEMPLE`
- 中央/主体区域展示 5 个占卜模式入口卡片
- 页面整体宽度与 tavern/treehole 统一

5 个模式入口：
1. 单牌：对答——启示
2. 二牌：修炼——结果 + 对策
3. 三牌：经典圣三角——过去 + 现在 + 未来
4. 三牌：决策——心态 + 现状 + 结果
5. 五牌：大阿卡那十字——有利因素 + 阻碍挑战 + 真相 + 根源 + 结果

不保留旧版“仅自己可见”的历史占卜列表。

### 2. 占卜页 `/temple/[spread]`

职责：负责完整占卜流程。

页面内容：
- 使用背景图 `F:\CODES\北斗镇\占卜酒馆占卜背景图.png`
- 左上角标题显示当前牌阵模式名
- 中央区域先显示问题输入框
- 提交问题后，牌阵按模式配置缓慢浮现
- 用户只能点击当前高亮的那张牌
- 所有牌翻开后，底部自动开始 AI 流式解读
- AI 解读区域使用 **站酷小薇体**

整个流程在**同一页完成**，不会跳到单独结果页。

## 牌阵模式定义

所有牌阵都由统一配置驱动，包含：
- `spreadType`
- `title`
- `subtitle`
- `cardCount`
- `positions[]`
- `layout`

每个 `position` 至少包含：
- `key`
- `label`
- `order`

### 模式 1：单牌 · 对答
- 数量：1
- 位置：
  - `guidance` → `启示`
- 布局：中央单牌

### 模式 2：二牌 · 修炼
- 数量：2
- 位置：
  - `result` → `结果`
  - `advice` → `对策`
- 布局：左右横向排列

### 模式 3：三牌 · 经典圣三角
- 数量：3
- 位置：
  - `past` → `过去`
  - `present` → `现在`
  - `future` → `未来`
- 布局：横向三牌

### 模式 4：三牌 · 决策
- 数量：3
- 位置：
  - `mindset` → `心态`
  - `situation` → `现状`
  - `outcome` → `结果`
- 布局：横向三牌

### 模式 5：五牌 · 大阿卡那十字
- 数量：5
- 位置：
  - `support` → `有利因素`
  - `obstacle` → `阻碍挑战`
  - `truth` → `真相`
  - `root` → `根源`
  - `outcome` → `结果`
- 布局：十字固定结构
  - 左：有利因素
  - 右：阻碍挑战
  - 上：真相
  - 下：根源
  - 中：结果

## 占卜页状态机

### 1. `idle`
- 显示标题、返回按钮、问题输入框
- 尚未显示牌阵

### 2. `summoning`
- 用户提交问题后进入该状态
- 输入区收起或弱化
- 对应数量的牌背在中央区域缓慢浮现到各自阵位

### 3. `revealing`
- 进入逐张翻牌阶段
- 只有当前该翻开的牌可以点击
- 当前牌使用高亮/辉光/脉冲作为明确提示
- 未轮到的牌保持牌背，禁止点击
- 已翻开的牌显示正面与正逆位

### 4. `interpreting`
- 全部牌翻开后自动触发 AI 解读
- 页面下方开始流式展示内容
- 上方牌阵保持可见，供用户边看边读

### 5. `complete`
- 解读结束后停留在完整结果态
- 用户可完整阅读全部内容
- 提供重新占卜或返回主页入口

## 单张牌展示规则

翻开的每张牌下方固定显示两行：

1. **指示方向**
   - 例如：`结果` / `启示` / `对策` / `真相`

2. **牌面信息**
   - 格式固定为：
     - `「XII」倒吊人 正位`
     - `「0」愚者 逆位`

说明：
- 编号使用 **罗马数字**（用户已确认）
- 文案中明确显示 **正位 / 逆位**
- “指示方向”与“牌本身”是两行分开的，不混在一起

## AI 解读格式

AI 解读必须采用**固定结构**，不能自由散漫输出。

### 输入给 AI 的信息
至少包括：
- 用户问题
- 当前牌阵模式名
- 每张牌的：
  - 指示方向
  - 罗马数字编号
  - 牌名
  - 正位 / 逆位

示例输入结构：
- 问题：……
- 模式：大阿卡那十字
- 抽到的牌：
  - 有利因素：`「XIX」太阳 正位`
  - 阻碍挑战：`「XV」恶魔 逆位`
  - 真相：`「II」女祭司 正位`
  - 根源：`「XIII」死神 正位`
  - 结果：`「XI」正义 逆位`

### 输出格式固定为三段结构

#### 1. 问题回响
- 1 小段
- 用较克制的语气重述问题核心与矛盾焦点

#### 2. 逐牌解读
- 每张牌单独一段
- 段首必须包含：
  - 指示方向
  - 罗马数字编号
  - 牌名
  - 正位 / 逆位
- 例如：
  - `有利因素 · 「XIX」太阳 正位`
  - `阻碍挑战 · 「XV」恶魔 逆位`

#### 3. 总结启示
- 最后一段统一收束
- 给出整体理解、趋势判断、提醒或建议

### 展示方式
- 全部翻牌后**自动开始**
- 采用**流式出现**，不是一次性整段展示
- 字体使用 **站酷小薇体**

## 数据模型调整建议

当前的 temple 数据结构偏向“固定三张牌 + 私人历史记录”。这次建议升级为面向多牌阵的结构。

### 保留 `TarotReading` 主体，但扩展语义
每条占卜记录建议至少包含：
- `id`
- `question`
- `spreadType`
- `reading`
- `createdAt`

### 每张抽到的牌建议记录为结构化子项
每张牌至少包含：
- `positionKey`
- `positionLabel`
- `cardKey`
- `cardNameCn`
- `romanIndex`
- `orientation` (`upright` / `reversed`)
- `imagePath`
- `revealOrder`

如果当前 Prisma 结构已经能存 cards 子表，则沿用关系模型；如果当前是固定字段或不够表达，则需要迁移到更通用的 cards 结构。

### 牌库数据
新增一份 **22 张大阿卡那元数据表/常量配置**，每张牌至少包含：
- 唯一 key
- 中文牌名
- 罗马数字
- 正面图片路径

另需单独配置：
- 统一牌背图片路径：`F:\CODES\北斗镇\talo_images\塔罗牌牌背.png`

## 视觉与排版要求

### 总体风格
- 参考 tavern / treehole 的页面外壳与宽度
- 标题置于左上角，使用相同衬线气质
- 玻璃感、暖色微光、简洁大气
- 不做功能后台风，不做卡片堆砌的仪表板风格

### 按钮与交互元素
- 能用图形 UI 表达的尽量不用大段文字按钮
- 风格参考 tavern/treehole 当前按钮体系
- 当前可翻牌需有明确视觉提示
- 禁止点击的牌不应出现“像能点但点不动”的假交互感

### 解读区
- 固定放在页面下方
- 使用站酷小薇体
- 分段清楚，避免整块大段挤在一起

## 动画策略

只做克制、稳定、能增强仪式感的动画：

- 牌阵浮现：透明度 + 位移 + 轻微缩放
- 翻牌：Y 轴翻转或轻量正反面切换
- 当前牌高亮：辉光 / 呼吸感边框
- 解读出现：流式逐段显示

不做：
- 夸张粒子特效
- 重型 3D 卡顿动画
- 音效系统

## 风险与实现注意点

1. **现有 temple 页面与数据模型可能过于绑定“三张牌历史记录”**  
   重做时需要优先确认 Prisma 与 DTO 是否支持多牌阵结构，否则要做迁移。

2. **图片路径与资源命名需要统一**  
   22 张牌正面与牌背应建立稳定映射，避免前端靠字符串猜测文件名。

3. **流式 AI 展示需要与当前项目 AI 调用模式对齐**  
   如果现有 temple action 是一次性返回，需要决定是否前端模拟分段展示，或服务端直接生成结构化字符串后前端分块渲染。

4. **严格顺序翻牌意味着前端状态要很清晰**  
   建议把当前可翻 index 作为单独状态，不把“是否允许点击”散落在多个条件里。
